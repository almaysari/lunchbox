# حالة التحقق — ما ثبت محليًا وما لم يُختبر بعد

> آخر تحديث: 2026-07-16.
> القاعدة الصارمة في هذا المشروع: عبارة «Zoho اكتشف/أعاد X» لا تُستخدم إلا
> لنتيجة جاءت من **Live Zoho API Discovery** بعد OAuth حقيقي. أي نتيجة من
> الوضع التجريبي تُسمى **Mock Discovery**، وأي مقارنة بالقائمة المرجعية تُسمى
> **Fixture Validation**.

## ✅ تم اختباره محليًا (Mock + اختبارات آلية — ليس إثباتًا عن حساب Zoho الحقيقي)

- Mock Discovery: اكتشاف مؤسسي كامل ضد محاكي Zoho محلي.
- Fixture Validation: مطابقة 20/20 مع القائمة المرجعية **ضد الـMock فقط**.
- تصنيف الأنواع (shared_mailbox / user / distribution_list / stream_group).
- التقاط الـAliases وتخزينها ومنع تسجيل alias كصندوق مكرر.
- استخراج مستويات الوصول الثلاثة والأعضاء والمشرفين وعدادات الـModeration.
- الفصل بين طابور المراجعة والأرشيف (moderation ≠ archive).
- منع التكرار على مستوى المنصة (معرّف المزوّد + بصمة Message-ID).
- محلل eDiscovery (ZIP/EML/MIME) واستيراد الأرشيف بالمجلدات والمرفقات.
- مزامنة Pilot قراءة-فقط ببوابة صريحة **باستخدام بيانات Mock**.
- تدفق OAuth كود-إلى-توكن **ضد الـMock** (وليس ضد خوادم Zoho).
- 13 اختبارًا آليًا تغطي ما سبق.

## ❌ لم يُختبر بعد (يتطلب OAuth حيًا على حساب Exotic Colors)

- OAuth الحقيقي مقابل `accounts.zoho.com` (أو مركز بيانات آخر).
- الـOrganization ID (zoid) الحقيقي.
- استجابة Groups API الفعلية لحساب Exotic Colors (أسماء الحقول الفعلية
  لمؤشر النوع والـaliases قد تختلف عن المحاكي — المحرك يلتقط عدة صيغ
  ويخزن الخام دائمًا، لكن هذا غير مثبت على حسابكم).
- اكتشاف الصناديق العشرين من Zoho الحقيقي.
- صلاحية حساب الأدمن فعليًا على كل صندوق.
- الوصول الحقيقي إلى المجلدات والرسائل والمحتوى.
- القراءة الحية لرسائل الـShared Mailbox (السؤال المفتوح الأهم — يُحسم
  حصريًا بفحص القدرات الحي، خاصة `organization/{zoid}/accounts`).
- تنزيل مرفقات حقيقية.
- حدود معدل Zoho الفعلية تحت حمل الاكتشاف والفحص.

## كيف يُقفل هذا الملف

تشغيل **Live Zoho API Discovery** من لوحة الإدارة على حساب الشركة، ثم نقل
كل بند من القائمة الثانية إلى الأولى مع رابط دليل (تقرير `detection_reports`
المعقّم الخاص به). لا يُعتبر أي بند مثبتًا قبل ذلك.

## ضمانات الفصل بين الوضعين (مطبقة في الكود)

- الوضع التجريبي يستخدم قاعدة بيانات منفصلة كليًا (`data-demo/`) — بيانات
  الـMock لا يمكن أن تتسرب إلى سجل Live.
- القائمة المرجعية (`test/fixtures/expected-mailboxes.json`) تُقرأ فقط في
  خطوة المقارنة بعد الاكتشاف؛ لا يوجد أي مسار كود ينشئ صناديق منها.
- الواجهة تعنون النتائج صراحةً: «Mock Discovery — ليست Zoho الحقيقية» في
  demo، و«Live Zoho API Discovery» في live.
- الجدولة التلقائية لا تلمس أي صندوق لم يبدأ الأدمن مزامنته يدويًا
  (`sync_enabled` لا يُرفع إلا بزر البدء الصريح).
